# The cache relay (-experimental-relay)

Written 2026-10-23.

## What it does

Claude Code marks for the cache only the system prompt and the last
messages, and can't be told where else. To keep the view cached, opt-chat
sends the view up to its last multiple of 64 lines as a message of its
own and waits for the model's "ok" (the ack). That costs a request per
call, a rewrite of the whole view each time the view passes a multiple of
64 lines, and the lines after that point are read anew by every call.

With `-experimental-relay`, opt-chat starts a relay on a loopback port
with a random path and gives every `claude -p` call
`ANTHROPIC_BASE_URL` pointing at it. opt-chat sends the view whole, with
no ack. The relay forwards each request to `https://api.anthropic.com`
with its headers as they came, and changes only the body of
`POST /v1/messages`. It lays the request out as the recipe's §3.3 does:

- The view (`<chat>` ... `</chat>`) goes in blocks of 4 lines from its
  start. A mark sits on the last whole block, and two more sit 20 and 40
  blocks before it, as pi-optchat places them. The API looks back up to 20
  blocks from a mark for an entry. So the next call, its view longer by up
  to 240 lines, reads this call's entry and pays only for the new lines.
- Claude Code's environment block, when it comes as a system message
  after the view's user message, moves before the view. An assistant "ok"
  follows it, because the API refuses a system message followed by a user
  message (400, checked). The block then sits in the prefix that every
  call shares.
- The API takes four marks. The relay keeps them in this order: Claude
  Code's marks after the view (its turn's tool calls read them back), the
  view's last whole block, the two earlier view marks, the marks before
  the view, then the system prompt's.
- Marks use the TTL of Claude Code's own marks. That is 1 hour on a
  subscription, as the recipe says.
- Single flight, as UniiChat's `AskAI.wait`: a call whose marked prefix
  another call is writing waits until that call's response begins, then
  reads the entry. Compactions start up to 8 at once on one view.

The relay starts only when none of `ANTHROPIC_BASE_URL`,
`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` or the Bedrock, Vertex and
Foundry switches is set, so it never moves a call to another account or
to API billing. A body it can't parse, or one with no view, goes on as it
came. `OPT_CHAT_RELAY_TRACE=<file>` appends each request's shape (roles,
block counts, marks, short hashes of the prefix's parts) and the API's
error bodies, never text or headers.

The same work fixed one thing outside the relay. The MCP server encoded
`tools/list` without sorting map keys, so the `spawn` and `tell` schemas
came out in a different key order from call to call. Tools head the
cached prefix, so a compaction that drew a new order wrote everything
again. `TestMCP` now checks that 20 calls give the same bytes.

## Measured

Throwaway chats of 400 to 700 made-up notes, Haiku 5.5, effort low, the
user's Claude Code setup on. Each number is one turn's `[context ...]`
line, in tokens. "Before" is the first version of this flag (dfbbae8:
64-line first message, relay marks only that). "After" is this layout.
Runs went on two chats at once and then swapped.

| scenario | before: read / write / uncached | after: read / write / uncached |
|---|---|---|
| steady turns, about 40 lines past a 64-line cut | 41.5k / 0 / 1.6k | 44.8k / 0 to 0.1k / 0 to 0.1k |
| 30 new lines per turn | every other turn 6.2k / 39 to 45k / 0.2k; else 45k / 0 / 1.1k | 46 to 49k / 0.9k / 0 |

On 100 new lines per turn, the recipe's one mark against pi-optchat's
three:

| | one mark | three marks |
|---|---|---|
| per turn | 18.8k / 24 to 44k / 0.1k | 48 to 63k / 3.1k / 0.1k |

One step in the three-mark run fell in a view batch, which rewrites the
view in any layout (recipe §3.3).

## Risks

- Claude Code's request layout is not an interface. It has put the
  environment block both in a system message and in the first user
  message. A layout the relay doesn't recognise goes on unmarked, which
  costs cache, not correctness.
- The relay sees the OAuth token in transit. It forwards headers and
  never reads, logs or stores them.
- A relay that can't reach the API answers 502, which Claude Code
  retries like any network error. There is no per-call fallback to a
  direct connection.
- The "ok" message the relay inserts reads to the model as its own reply,
  as the ack's real one did.
